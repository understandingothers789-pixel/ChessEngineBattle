# ChessEngineBattle 0.3.0 engineering report

Baseline: f693c12d8e48d9bc91bbf843d915f3a3abbcb808, development/0.2.0.
Delivery branch: development/0.3.0. Main and development/0.2.0 remain unchanged.
The release commit and verified Windows artifact are recorded below after CI.

## Architecture and completed work

Preserved Nocturne's pinned board, rules, PV renderer, UCI transport and existing
continuous/independent collectors. Added coherent modules: experiments.py for
persistent sequential scaling conditions, experiment_ui.py for builder/results,
comparison_ui.py for candidate matrix/heatmap, game_browser.py for Qt model/view.
Existing search, storage, statistics and panel modules are extended in place.

Played moves now persist an exact source-run link, including pre-move position,
ply, profile, limit, final bestmove, committed move and completion status. Current
and archived tournament settings are committed in one SQLite transaction. Original
Thinking loads that source rather than a newer compatible run. Old records remain
readable, with explicitly uncertain legacy attribution. Additive payload schema
version 3 makes a SQLite backup before activation and never rewrites old records.

Checkpoints preserve highest-crossed-only semantics and requested/actual nodes.
Rank freshness stores observation sequence, updated-on-this-event, nodes and depth.
Regressing observations are rejected per rank; mixed-depth ranks remain distinct.
Rank ordering no longer depends on insertion order; absent rank 1 is never
promoted from rank 2. Duplicate roots retain their lowest explicit rank. Final
bestmove remains independent of checkpoint data. Independent storage-limit errors
are handled as failed searches. Configurable search-silence timeout defaults to
120 seconds; advanced setting 0 disables it for legitimately silent engines.
Node/depth validation is integer-only, nodes supported through 2^63−1, and tested
above 2^53 through actual UCI commands. Resume remains idempotent. Failure fixtures
exercise process exit, illegal moves, silence, no-info completion and cleanup.

Panels add checkpoint sliders, previous/next and explicit Final Result selection,
compact metadata mode and per-rank freshness tooltips. Candidate matrix and
heatmap use recorded ranks only; clicking a cell restores its snapshot and PV.
Graphs offer evaluation or depth and hover details, maintaining run separation.
Candidate milestones are clickable; retained Nocturne PV divergence and hover
preview behavior remains unchanged. The game browser uses QAbstractTableModel
and a proxy: only changed rows emit updates, numeric sorting and filtered source
mapping are tested on 2000 games. State scanning and full JSON persistence are
still linear; this release does not claim a fully incremental database pipeline.

Node Scaling Experiment uses the selected Engine A profile, book/pairs/seed and
playing MultiPV. Positive integer ratios build separate persisted tournaments
with identical opening paths, seed and reversed-color schedule, independent game
IDs and search contexts. A shared sequential runner advances conditions, pauses,
resumes and restores progress. Results show per-condition W/L/D, score, B-over-A
Elo, interval availability, completed pairs/clusters, and a log-ratio graph. Opening
a condition's games requires pausing active work. JSON exports preserve conditions,
configuration, attributed moves, matching searches/snapshots and statistical
methodology; unbounded estimates are explicitly represented as such.

## Statistical methodology

Replace independent-pair normal intervals with seeded exploratory opening-cluster
percentile bootstrap (2000 replicates). Color-reversed pairs stay intact; repeated
opening paths are resampled together rather than treated as independent games.
Require at least 10 opening clusters and varying scores. Degenerate intervals are
reported unavailable. Logistic Elo uses raw score, reporting unbounded estimates
at 0/1. Incomplete pairs affect descriptive score but not paired intervals.

Assumes independent sampled opening clusters. Related but nonidentical openings,
transpositions with different paths, and common engine/hardware effects can still
create dependence. Percentile bootstrap is exploratory, not a formal small-sample
or sequential strength test. Multiple ratio comparisons do not establish a smooth
scaling law. SPRT and fixed-gain claims are deliberately absent. The graph excludes
unbounded/missing Elo and clips interval bars to its visible scale.

## Validation and independent second review

Full regression command: QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q.
64 passed; 1 optional real-engine test skipped (no supplied/installed engine).
Optional path: set NOCTURNE_UCI_ENGINE to a trusted local executable and rerun
`tests/test_real_engine.py`. It exercises discovery, limits, MultiPV 1–5 where
advertised, cancellation, independent searches and a short self-play tournament.
No engine was downloaded or bundled; real-engine compatibility/strength is untested.

Second correctness review found and fixed duplicate-root rank overwrites,
degenerate bootstrap precision, and inconsistent adjudicated PGN result markers.
One pre-existing fixture incorrectly labeled rank 2 as multipv=1; its metadata was
corrected while retaining its assertions, and malformed/missing rank coverage was
added. Tests also cover migration backups, interrupted source links, newer-run
misattribution, huge integer transmission, condition separation/recovery,
incremental notifications, heatmap selection and repeated-opening dependence.

UX review inspected actual offscreen rendered windows at 1920×1080 and 1280×800
with long profile names and MultiPV 5, including the heatmap. Improvements after
inspection: shorter human-readable run labels, FEN moved to a tooltip, shared-move
text cues independent of color, empty game table hidden, and a persistent status
bar. Node Scaling has a direct workspace entry. At small resolutions PV panels
scroll; Compact hides metadata. Dark appearance was inspected; light appearance
and interactive physical Windows desktop testing were not performed.

Linux PyInstaller and packaged offscreen startup/render smoke pass. Windows CI
runs the complete suite, builds PyInstaller and runs the packaged render-and-exit
check before uploading an artifact. This is automated CI validation, not real
Windows desktop interaction. Successful artifact details follow after CI.

## Remaining work and priorities

P2 clocks/increments/forfeits, concurrency/resource admission, SPRT, richer book
filtering/Polyglot, whole-game queues and storage cleanup are not implemented.
No inactive placeholder modes were introduced. Candidate-specific graph traces,
major-PV/evaluation/cross-engine agreement milestones, custom independent-budget
lists, rich workload estimates, experiment archive navigation beyond the latest
experiment, and reopening another condition during an active one remain future
work. Experiments continue sequentially; supplementary work requires pausing.

Next priorities: real-engine and interactive Windows validation; more exhaustive
reliability fixtures; explicit experiment archive browsing; richer discovery
milestones and candidate traces; profiling large database saves; then clocks and
coordinated resource admission before concurrent execution.
