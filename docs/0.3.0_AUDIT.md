# 0.3.0 audit before implementation

Starting source: f693c12d8e48d9bc91bbf843d915f3a3abbcb808, verified against
remote development/0.2.0. New branch: development/0.3.0. Main and 0.2.0 preserved.

Reuse existing visual engine editor, Nocturne board/PV/UCI infrastructure,
continuous and independent capture, run selectors, archive lookup, fixtures,
paired schedules and Windows packaging. Do not duplicate these systems.

Confirmed defects: move attribution uses newest compatible run; milestones use
insertion order rather than MultiPV rank; Limit.validate converts integers via
math.isfinite; independent storage failures escape the Qt callback; table rows
are rebuilt on every move. Rank-specific nodes/depth survive but freshness does
not distinguish unchanged ranks. Statistical intervals assume independent pairs,
ignoring repeated openings. These are correctness work, not optional cosmetics.

Optional improvements: candidate matrix/heatmap, node-scaling builder, grouped
uncertainty, incremental model/view, custom independent budgets. Clock support,
concurrency and SPRT remain stretch goals. No real engine is presently registered;
integration tests must accept explicit executable paths and never download one.

Data changes will be additive JSON fields using existing SQL tables. Back up the
SQLite database before advancing the payload schema version. Preserve records
without source attribution and label any historical fallback uncertain.
