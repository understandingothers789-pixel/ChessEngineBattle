## Changed components

`app.py`: workspace navigation, sortable/filterable game table, clickable moves,
original-thinking action, archive browser, summaries, readable budgets, geometry,
live candidate separation, independent job queue, PV divergence highlighting,
recent-book selection and opening previews. `widgets.py` extracts the visual
profile editor, run-isolated analysis panel and evolution graph. `statistics.py`
adds a documented paired-score normal interval mapped to logistic Elo.

`model.py`: additive search final-result storage, run lookup, archive lookup,
opening sequences/names and readable budgets. `history.py`: logarithmic matching
and first-observed candidate milestones. `runtime.py`: persisted final bestmoves,
independent final-result snapshots, idempotent Resume, bounded UI notification
frequency without dropping checkpoint observations, maximum-length termination.
Packaging workflow: development-branch builds and packaged Windows render smoke.

## Correctness and persistence

Existing SQL schema and rows remain intact; changes are additive JSON fields
with defaults for old searches. No destructive schema migration occurs. Nocturne
remains pinned to 5f9c695: upstream f1073e0 only adds unrelated Leela speed limits.
Original licenses and assets are preserved. No engines or networks are bundled.

Continuous captures retain the original complete-rank gate and highest-crossed
threshold semantics. Missing intermediate thresholds are displayed, never
synthesized. Every line retains its own depth/nodes; mixed-depth ranks are labeled.
Final results (including useful partial lines) persist separately from continuous
checkpoints. Independent jobs store one final snapshot per separately requested
budget, with reported nodes, bestmove and completeness. Search-run selectors
include empty/incomplete runs and never merge unrelated histories into one graph.
Cache identity retains exact FEN, repetition path, executable/config/network hash.

Live panels no longer depend on historical selection. Clicked moves and previews
operate on a separate game copy. Original-thinking navigates to the position
before the selected move and selects its playing run where available. Resume
while active is a no-op. Main startup uses a QLockFile to detect a second instance.
New PGN openings retain their full legal path; existing FEN-only archives remain
unchanged and cannot retrospectively recover lost opening paths.

## Remaining work

This release focuses on P0 and a portion of P1, not the entire requested roadmap.
P2 classical clocks/increments/forfeits, concurrent game scheduling/resource
allocation, and SPRT are not implemented. Do not select these unsupported modes.
Independent jobs currently use doubling budgets from first checkpoint to each
engine's node budget, not an arbitrary custom budget list. Supplementary jobs
still require paused tournament resources. Archive deletion/cleanup, selective
export, storage-limit UI, deeper grouped statistics, evaluation-book filtering,
Polyglot, drag/drop imports, engine-crash restart controls, optional evaluation
adjudication, and whole-game comparison batching remain future work.

Statistics use independent *pair scores*, with an approximate normal interval
only for at least 10 complete, varying pairs; this is descriptive and needs a
stronger small-sample model before formal testing. Scores can saturate to infinite
Elo at all-win/all-loss boundaries. Milestones cover candidate appearance, best
move changes and disappearance; evaluation/PV-change and cross-engine-agreement
milestones remain incomplete. Maximum game length defaults to 1000 plies and is
stored/read by runtime, but lacks a dedicated configuration control. Large game
tables still repopulate on updates and need incremental models for long events.

Next priorities: interactive Windows/real-engine testing; incremental game models;
formal pair-aware uncertainty; clock accounting with timeout fixtures; coordinated
resource admission before concurrent execution; archive cleanup and selective
scientific exports. Preserve all old download links when adding new builds.
