# 0.3.3 speed and bug review

Performance changes:
- Stream SHA256 in bounded 1MB chunks and cache up to 32 executable/network
  identities using resolved path, device/inode, size and nanosecond modification /
  change timestamps. Recheck metadata on every lookup; reject a file changing
  during hashing. This avoids rereading unchanged engine binaries every move.
- Reuse the separate viewer game when its existing moves are a legal unchanged
  prefix of the new history, appending only new moves. Rebuild for game changes,
  historical cursors or changed history. The running game remains independent.
- Recompute/render match statistics only when results change, remove redundant
  totals and duplicate analysis-history refresh, and restrict browser updates to
  the previous/current game rows. Full rebuild remains available on new matches.

Confirmed bugs fixed:
- Selecting a game in the sorted browser did not update the hidden selection used
  by Original Thinking and supplementary provenance.
- Preview pin checkboxes could stay checked after the actual pin was cleared.
- Pending experiment transitions could overwrite an unrelated new tournament.
- Unsupported MultiPV was labeled interrupted instead of failed.
- Numeric tooltips described an outdated current value after editing the control.

Validation: 73 tests pass, 1 optional real-engine test skipped. New regressions
exercise hash hits/invalidation/deletion, incremental replay and independence,
selection and pin consistency, and experiment isolation. Existing search, history,
export, engine setup and tooltip tests remain passing. No real engine was used.

Reproduce local microbenchmarks with `.venv/bin/python benchmarks/update_paths.py`.
On this instance, executable identity checks (100 calls, first call cold) fell
from 1995.515 ms to 25.883 ms. A 2000-game model took 58.014 ms for 100 full scans
versus 0.078 ms for 100 single-row updates (no rendering). These are local
application-overhead measurements, not real-engine speed or strength claims.
Raw 80-ply replay timing remains about 0.5 s/100 runs; the optimization avoids
replaying old moves rather than changing Nocturne's rules implementation.

Remaining limits: full tournament JSON saves and experiment state copies are
still proportional to history size. File metadata-based caching detects normal
file changes but is not a security boundary against adversarial filesystem
manipulation. Confidence models, playing rules and checkpoint semantics are
unchanged. No engines or networks are bundled. Build remains unsigned; Smart App
Control trust and interactive Windows use are not validated by CI smoke tests.

The Windows artifact and source commit are recorded after CI succeeds.
