# 0.3.5 paired openings and increment clocks

Built from the user-confirmed 0.3.4 application branch. Packaging specification
and dependency requirements are retained; only normal version resources advance.
New branch development/0.3.5 preserves the earlier builds as fallbacks.

## Opening rematches

Color-reversed pairs were already the standard schedule. Match Setup now shows
pairs × 2 games explicitly. Play every book opening twice sets the pair count to
the number of entries in the selected PGN/EPD suite. This is an explicit action,
so manually chosen game counts are not overwritten. Each entry is assigned one
game per color with the exact same starting path/position. Larger custom pair
counts cycle through the suite; duplicate entries are not deduplicated.

## Clock mode

Choose clock in Search mode. Configure each engine's base time in minutes and
increment in seconds, or apply a shared 1+0, 3+2, 5+3 or 10+5 preset. Node/depth
budgets and ratio controls are hidden in clock mode. Review & Start Match is now
always accessible in the top action row. Node/depth/fixed-movetime modes retain
their existing behavior. Supplementary analysis requires one of those explicit
search budgets, not the playing clocks.

clocks.py owns integer nanosecond accounting. runtime.py uses a narrow adapter
on the existing Nocturne connection.request API to replace only the UCI go command
with wtime/btime/winc/binc. No alternate UCI transport, engine controller, board
or snapshot system is introduced. No depth, node or movetime cap is silently
combined with game clocks. Tests inspect the actual protocol commands.

Time starts when Nocturne sends go, excluding process startup/option preparation.
The application-receipt timestamp of bestmove stops the clock; legal accepted
moves earn increment. A late move earns neither a move nor an increment. A live
50ms timer also stops a silent engine on expiry. Time forfeits draw if python-chess
reports the opponent has insufficient mating material; otherwise the opponent
wins. Protocol crashes/illegal moves still pause for investigation rather than
being silently adjudicated as strength losses.

Pause debits elapsed time without an increment and freezes the clocks. Resume
starts a separate search with the remaining budget. Clock state is saved on start,
accepted moves, pause and terminal events. Clean application close pauses. After
an unclean exit, recovery debits elapsed wall time, INCLUDING downtime, from the
saved running side; it does not grant fresh time. A system wall-clock correction
can affect that recovery estimate. Normal in-process timing is monotonic.

Each new game resets clocks; reversing colors also reverses the appropriate
engine budgets/increments. Live clocks remain labeled live while browsing earlier
games. Source-move links retain elapsed time and before/after clock states; JSON
exports preserve them, and search metadata stores the actual go command. PGN uses
TimeControl for equal controls and WhiteTimeControl/BlackTimeControl plus unknown
TimeControl for asymmetric controls, avoiding the misleading multi-stage colon
notation. Termination and result are retained. Historical clock annotations are
not yet shown as per-move PGN %clk comments or a separate replay-clock UI.

## Validation

87 tests pass; 1 optional real-engine integration test is skipped. Fourteen new
clock/rematch cases (including parameterized invalid limits) exercise deterministic
accounting, no increment on flag, reversed UCI clocks, paired resets, forfeit and
late-result rejection, pause/resume, unclean recovery, insufficient-material draw,
UI settings, full-suite pair counts and asymmetric PGN headers. The old invalid
mode fixture was changed from clock to unknown now that clock is supported.
All previous regressions remain passing. Offscreen UI was inspected at 1920×1080.

Clock accounting uses application receipt, so event-loop/OS scheduling delays can
influence very short controls; UCI clocks are rounded down to integer milliseconds
with a minimum transmitted positive remainder of 1ms. No pondering or separate
move-overhead allowance is implemented. This release does not claim tournament
arbiter certification or real-engine/interactive Windows validation. Default
controls are minutes rather than millisecond benchmarks.

Windows CI tests, packages and smoke-tests the executable. Its verified download
and source commit are appended after success. No engines or networks are bundled.
